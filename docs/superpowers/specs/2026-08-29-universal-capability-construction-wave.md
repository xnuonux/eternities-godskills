## decision

The 48 evidence-backed implementation targets from the certified Wave 2 semantic refinery will become a universal first-party capability layer. The system is not a Lunari subsystem. It is provider-neutral, agent-neutral, product-neutral, organization-neutral, embodiment-neutral, and Realm-neutral. Lunari, Godagents, coding agents, research systems, websites, games, robots, and future Eternities environments are consumers of the same portable contracts.

The existing 21 Godskills remain the compact top-level capability owners. Twenty-two focused operational skills become exact delegates beneath those owners. Twenty-six mechanisms extend the route and evidence contracts of existing Godskills. This preserves progressive disclosure and prevents a flat catalog of overlapping prompts.

## universal law

```text
capability != authority
skill != agent
agent != model
owner Godskill != operational delegate
equipped capability != permission to execute its effects
Lunari compatibility != Lunari ownership
fixture proof != universal behavior proof
```

No skill may derive authority from a user request, agent identity, product integration, archetype, embodiment, provider, or source repository. Effects remain bounded by the invoking host and, for Godagents, by the host policy and Realm Contract.

## architecture

### top-level Godskills

The existing 21 Godskills remain categorical owners. Their compact entrypoints continue to answer whether a broad capability family applies, choose one bounded route, preserve authority and effect boundaries, and load only the reference needed for that route.

No new top-level Godskill is created merely to satisfy a quota. A new Godskill requires a coherent purpose, distinct ownership boundary, repeated demand, non-overlap with existing owners, and measurable routing improvement.

### operational skills

Each operational skill owns one focused mechanism. It contains:

- a discriminating `SKILL.md` entrypoint;
- a neutral capability contract;
- exact source-cluster and review provenance;
- direct, paraphrased, contextual, exclusion, conflict, authority, effect, failure, and termination cases;
- a declared owner Godskill and optional supporting Godskills;
- an evaluation and terminal promotion receipt;
- no copied source prose, provider identity, slash-command dependency, or ambient authority.

Operational skills may be invoked directly by compatible agents or delegated to by their owner Godskill. They do not become competing categorical owners.

### Godskill extensions

Each extension adds a bounded route specialization to one existing owner. Extensions live in exact owner reference registries rather than inflating or mutating receipt-bound top-level entrypoints. The portable router manifest loads an owner registry only after the immutable owner has been selected and the request matches an extension trigger.

Every extension records its cluster digest, review digests, intended owner, required evidence, allowed outputs, forbidden effects, handoff owners, and termination condition. An extension cannot widen the owner's authority or convert a read-only route into mutation authority.

### deterministic priority ledger

All 48 targets receive a deterministic priority score used only for build order. The score is independent of Lunari and uses six declared dimensions:

1. cross-domain applicability;
2. compositional leverage;
3. mechanism distinctness;
4. evidence and testability;
5. authority neutrality and safe local operation;
6. implementation tractability.

Product-specific demand may choose which already-certified capability to use, but it cannot alter the universal construction evidence or retroactively change promotion.

### portable capability manifest

The release emits one content-addressed portable manifest containing every promoted top-level and operational capability. Each row includes:

- stable capability id and tier;
- owner Godskill id;
- exact entrypoint and contract digests;
- capability, effect, risk, evidence, and precondition vocabulary;
- direct versus delegated invocation status;
- argument-schema digest when applicable;
- composition and termination limits;
- promotion-receipt digest.

Consumers receive the manifest or selected entrypoint identities, never the full quarry. The manifest is deterministic and contains no host paths, credentials, provider routing, private session data, or product-specific authority.

## Godagents compatibility

Godagents already enforce the correct boundary: `routeGodskill` forwards ordinary mission text and a host-supplied context, accepts only selected entrypoints, checks that compiler authority and effects are subsets of host policy, and rejects malformed or oversized compositions.

This wave preserves that interface. The Godskills release will certify that:

- selected entrypoints retain `skills/<id>/SKILL.md` identity;
- compositions remain at or below the caller's maximum;
- operational delegates do not bypass top-level selection receipts;
- capability manifests never grant authority;
- no Godagent genome, expression, lineage, archetype, cortex, or embodiment can widen effects;
- Godagents can pin the exact portable manifest and release receipt without importing the repository quarry.

Godagents remain a separate repository and runtime. This wave will not edit their identity, keel, cortex, Realm, host policy, or creator implementation. It produces a compatibility receipt and exact handoff evidence for the Godagents development line.

## evaluation and promotion

Every target begins cold. A capability promotes only when:

- its exact Wave 2 cluster and review evidence reconcile;
- its implementation is independently written;
- all critical direct, paraphrased, contextual, exclusion, conflict, authority, effect, failure, and termination cases pass;
- the strongest applicable current owner or native workflow is evaluated as baseline;
- no critical regression exists;
- every effect is resolved;
- the entrypoint stays within its token budget;
- at least one declared measurable improvement passes;
- the promotion receipt binds exact current bytes.

Targets that fail a gate remain experimental, deferred, rejected, or unverified. Completion means every target has an exact terminal receipt, not that every target is called promoted.

## completion gates

The wave is complete only when:

1. all 48 targets appear exactly once in the construction ledger;
2. all 22 operational targets have first-party artifacts and terminal receipts;
3. all 26 extension targets have exact owner registries and terminal receipts;
4. no target widens authority, activates a source instruction, or copies source prose;
5. the portable manifest is deterministic and bounded;
6. all existing routing and Godskill regression suites pass;
7. compatibility evidence matches the Godagents selected-entrypoint boundary;
8. an adversarial review has zero unresolved critical or important findings;
9. the complete repository suite passes from merged `main`;
10. no host profile, external account, third-party service, or product runtime is activated.

## proof limits

This wave can prove local deterministic contracts, fixtures, exact provenance, routing behavior, and portable package integrity. It cannot prove arbitrary live-model interpretation, universal domain correctness, production performance, provider behavior, legal clearance, external execution safety, or suitability for every future embodiment. Those claims require separate current evidence and authority.
