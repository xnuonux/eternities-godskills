# Quarry Total Infusion Design

## Purpose

Bring every one of the 7,776 inert Wave 2 skill bodies into the Eternities Godskills evidence system without bulk-installing, executing, copying, or pretending that unsafe or unreviewed third-party behavior is promoted.

## Completion contract

The infusion is complete only when:

- all 7,776 source ids appear exactly once in a terminal disposition ledger;
- all 3,581 unique body digests have one canonical representative;
- exact duplicates retain aliases and never consume separate runtime context;
- every canonical body is either rejected by exact security evidence or represented by one cold specialist facet;
- every facet belongs to one ontology family and one existing Godskill target;
- a bounded query returns at most five verified facets without loading the full atlas;
- the new Omnibus Godskill can retrieve a specialist and hand off to an existing Godskill without granting external authority;
- all generated artifacts are deterministic, digest-bound, and rebuildable;
- routing remains commandless, cold, bounded, and fail-closed;
- no third-party code, hook, binary, installer, or command is executed;
- no host profile, Pantheon, deployment, publication, or external account is changed.

## Architecture

`src/quarry-infusion.mjs` converts exact source, duplicate, and security ledgers into a canonical corpus. It reads only each `SKILL.md` body, extracts bounded structural metadata, classifies it through the existing ontology, and assigns terminal dispositions. `scripts/build-quarry-infusion.mjs` writes canonical JSONL artifacts and a receipt. `src/quarry-atlas.mjs` verifies the receipt and performs bounded lexical retrieval from the cold facets. `skills/eternities-omnibus` exposes that retrieval and delegates execution to the narrow existing Godskill selected by the family map.

## Terminal dispositions

- `canonical-facet`: unique, non-rejected body retained as inert pattern evidence in the atlas.
- `exact-duplicate`: byte-identical alias bound to its canonical facet or canonical rejected body.
- `security-rejected`: canonical body whose static ledger says `reject-before-indexing`.

`canonical-facet` is not a claim that the source implementation is safe, correct, current, or promoted. Manual-review findings, license uncertainty, provider binding, and sensitive surfaces remain attached to the facet and constrain use to pattern reference until stronger evidence exists.

## Family routing

The existing 21-family ontology is mapped to the narrowest promoted Godskill. The two ontology families without a same-named routing family use explicit mappings: `repository-source-research` to `eternities-oracle`, `verification-evidence` to `eternities-phoenix`, `visual-3d-motion` and `web-interface-accessibility` to `eternities-muse`, and `general` to `sovereign-skill-refinery`. Multi-family evidence retains all classifications but one deterministic primary target.

## Proof limits

Structural extraction and lexical retrieval do not prove arbitrary semantic equivalence, source correctness, production safety, current provider behavior, or legal compatibility. The system proves terminal coverage, exact provenance, deterministic classification, bounded retrieval, preserved risk evidence, and absence of automatic activation.
