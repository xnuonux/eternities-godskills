## the export step did not run, and that is not an oversight

Every prior intake finished with `export.mjs`, producing `production-briefs.json`. It cannot run
for this intake, for a reason worth recording:

```js
assert(clone.complete && clone.rows.length === 12 && ...)
assert.equal(scan.repositories.length, 12)
...
const summary = sourceSummaries[key];

```

summary exists for every skill file.** That gate is correct. The September 13 intake had eight
entrypoints and a human read all eight. This one has 386 files, and generating 386 machine
summaries to satisfy the assertion would put unreviewed text into the record under a field whose
whole meaning is "a person read this."

So the briefs remain outstanding, deliberately. What exists instead is a **reading order**.

## the instruction-priority flag is a false positive, 14 times

14 files carry `instruction-priority-or-forced-activation-reference`. **Both cases checked were
ordinary prose.**

- `garrytan/gstack:careful/SKILL.md:28` — *"User can override each warning. Use when touching
  prod, debugging live systems"*. The pattern matched `override` and `system` sixty characters
  apart.
- `Metta-AI/coworld:…/harness-sdk-protocol/SKILL.md` — matched the word `instructions` inside a
  paragraph about parsing a natural-language instructions string.

The flag is a coarse triage signal, not evidence of injection or forced activation. **Do not
report 14 flagged files as 14 findings.** The genuinely useful signal is the *combination* —
`gstack`'s deploy skills (`land-and-deploy`, `setup-deploy`, `ship`, `office-hours`) carry
credential *and* external-effect flags together, which is legitimate for deploy tooling and is
exactly why they need a slow read before anything is adopted.
