# Dependency-aware check runner

Implement `export async function runChecks(checks, targets, execute)` in `runner.mjs`, using only built-in JavaScript. This replaces a workflow that repeated shared prerequisite checks. No historical timing or token baseline is available. Deliver the implementation and your own focused tests, and briefly report what was verified and what savings are or are not established. Finish the coding work; no installation, network, external service, or user clarification is needed.

Contract:

- `checks` is an array of non-null records `{id, requires}`; `id` is a nonblank string, `requires` an array of nonblank string IDs. `targets` is an array of nonblank string IDs, and `execute` is a function. Missing fields, malformed array entries (including holes), duplicate check IDs, unknown dependencies/targets, or any dependency cycle must reject with TypeError before `execute` is called. Validate the entire declared catalog, even unselected checks. Additional record fields may be ignored. IDs are exact and case-sensitive: do not trim, case-fold, or treat object-property names specially.
- Only run selected targets and their transitive prerequisites. Traverse targets in input order and prerequisites in each record's order, depth first; produce dependency-first order. Execute each distinct reachable check at most once per call. Duplicate targets and duplicate prerequisite edges are allowed and do not repeat work. An empty target array yields `[]` after validation.
- Call `execute(id)` sequentially and await settlement before starting another check. A synchronous throw or rejected promise means that check failed. Resolution of any value means it passed. Do not retry. Independent selected work continues after a failure.
- A check whose immediate prerequisites failed or were blocked is not executed. Its result is `{id,status:'blocked',blockedBy:[...]}` with unique failed/blocked immediate prerequisite IDs in declaration order. Successful entries are `{id,status:'passed'}`; failures are `{id,status:'failed',error:message}` where message is Error.message for Error instances and String(reason) otherwise. Return one entry for every reachable check, including blocked checks, in the traversal order above.
- Do not mutate inputs or retain execution results between separate calls. Support ordinary bounded catalogs (up to 100 checks); no worker threads, parallel scheduling, wall-clock benchmark framework, or new dependencies are needed.
