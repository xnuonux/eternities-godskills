# eternities muse

Muse turns visual ambition into an authored, testable system. It does not add effects for their own sake, clone a reference, or replace the narrower skill that should build the final artifact.

Read [the operating contract](references/operating-contract.md) when the mission crosses multiple media, needs a formal acceptance matrix, or carries consequential brand and accessibility decisions. Keep the compact route below for a bounded task.

## route first

Choose exactly one dominant route:

- `visual-forensics`: extract identity, tokens, components, layout, accessibility, reconstruction rules, confidence, and unknowns from images, sites, or design files.
- `interface-art-direction`: settle the generative visual law, hierarchy, design tokens, component grammar, responsive behavior, and implementation handoff for a consequential interface or redesign.
- `motion-story`: shape an emotional arc across scenes or chapters, then specify causal motion, media beats, transitions, reduced-motion behavior, and performance tiers.
- `visual-acceptance`: prove a built visual system with deterministic captures, diagnostic states, temporal and device coverage, accessibility checks, budgets, invariants, and rejection criteria.

Skip copy changes, spacing fixes, and ordinary component edits. Once direction is settled, yield implementation and local asset selection to `eternities-frontend-arsenal` or `frontend-design`. Yield a direct final-image request to `imagegen`, fixed-window voice production to `narrator`, subtitle burning to `subtitles`, and a concrete visual regression or black canvas to `systematic-debugging`.

For mixed missions, settle the earliest unresolved route first and emit a handoff contract for the next specialist. Do not load every delegate at once.

## common laws

1. Establish the audience, desired effect, constraints, and one generative visual law before choosing decoration.
2. Separate observed, extracted, inferred, and proposed facts. Attach confidence and source pointers to consequential visual claims.
3. Resolve recurring decisions through named semantic tokens. Keep literal values in the token definition, not scattered through artifacts.
4. Treat accessibility, responsive behavior, loading, reduced motion, and GPU cost as design inputs rather than final polish.
5. Motion must reveal, orient, demonstrate, or cause the next beat. Idle movement and uncaused direction changes do not earn runtime cost.
6. Keep text and controls semantic and editable. Generated imagery may support a system but cannot carry essential interface meaning alone.
7. A beautiful frame is evidence only for that frame. Acceptance must exercise the mechanism and its intended operating envelope.

## route contracts

### visual forensics

Capture the strongest available source before interpreting it. Recover explicit variables and structure where available, then map identity, the single most distinctive visual carrier, tokens, components, layout, responsive states, accessibility, and reconstruction risks. Mark each consequential result high, medium, or low confidence. End with open questions and rules that prevent downstream imitation from drifting into unsupported invention.

### interface art direction

Name one visual law that can decide palette, type, spacing, shape, imagery, motion, and density together. Translate it into semantic tokens, component families, signature moments, breakpoints, interaction states, accessibility constraints, and a build-ready acceptance contract. If the brief is unresolved, compare at most three materially distinct directions and select one before implementation.

### motion story

Define opening state, turning point, climax, and closing residue. Give every scene a narrative job and every transition a visible carrier or cause. Select the lowest visual-compute tier that expresses the story, budget mobile and reduced-motion behavior from the start, and synchronize media to authored beats. Preserve a deliberate moment of stillness before a major result when the arc needs emphasis.

### visual acceptance

Freeze viewport, device tier, content, seed, camera, timing, and configuration. Compare final and stripped-down baselines, inspect relevant passes or states, cover representative extremes, record frame and memory budgets, and test keyboard, contrast, focus, reduced motion, responsive states, and fallbacks. Write invariants and explicit rejection thresholds before judging captures.

## termination

Finish when one route owns the mission, observed facts and proposals are distinguishable, the system has one coherent visual law, constraints and unknowns remain visible, the next specialist has a bounded contract, and acceptance can fail for stated reasons. Do not invoke Muse recursively.
