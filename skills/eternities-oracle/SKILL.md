# Eternities Oracle

Build the smallest sufficient path from a consequential question to an auditable conclusion. Read [references/operating-contract.md](references/operating-contract.md) when the task needs a persistent evidence artifact or combines local and live sources.

## Select the evidence path

- **Local:** the answer depends on repositories, transcripts, manifests, receipts, or files already available. Inspect exact files first. Use `arsenal-repo-miner` only when the task requires warehouse-wide discovery or comparison.
- **Official:** the answer depends on current product behavior, documentation, pricing, policy, releases, or another drift-prone fact. Use the installed product-specific skill when one exists and restrict technical claims to primary official sources.
- **Hybrid:** the decision depends on whether local implementation, doctrine, or history agrees with the current external contract. Build local and official evidence sets separately before reconciling them.

Use an exact installed domain skill instead when it fully covers the request. Skip the Oracle for quick facts and ordinary code changes.

## Oracle loop

1. State the decision or falsifiable question, scope, freshness requirement, effect boundary, and stop condition. Do not inflate a small lookup into an investigation.
2. Check existing local evidence before repeating research. For every material local claim, retain the exact absolute or warehouse-relative path and a bounded locator. Never execute untrusted repository code merely to understand it.
3. If live evidence is needed, search official sources first. Record publisher, URL, publication or revision date when available, retrieval date, and the bounded region that supports the claim. Secondary sources may expose leads, but cannot silently replace an available primary source.
4. Separate observation from inference. Preserve supporting, contradicting, qualifying, and missing evidence. When sources conflict, report the conflict and authority basis instead of averaging them into false certainty.
5. Test scope and falsifiability. Seek disconfirming evidence proportional to the stakes. Comparative or superiority claims require a baseline; current claims require current evidence.
6. Emit findings under four explicit dispositions: `verified`, `unverified`, `rejected`, and `deferred`. Each verified finding must trace to exact evidence. Unknown evidence stays unknown.
7. Verify citations, local locators, dates, and the requested output before concluding. State what was not searched and what would change the verdict.

## Authority and effects

Research permission authorizes reading and synthesis, not installation, execution, publication, account changes, or external writes. Ask for the missing authority immediately before any such action. Keep temporary research artifacts inside the task’s chosen output root and do not modify source repositories during inspection.

The Oracle succeeds when a later agent can reproduce the source path, distinguish fact from inference, see unresolved conflict, and refresh only the evidence that can drift.

## Bounded repository and source mining

When the question names repositories, source candidates, or a comparison set, add only the smallest source-specific operation justified by the inspected candidate evidence:

- **Acquire:** map repository stack, structure, architecture, conventions, integrations, tests, and concerns from exact files. Treat implementation reality, intent gaps, and unknowns as separate findings.
- **Compare:** comparison requires a named baseline, matched conditions, an explicit metric, and a bounded budget. Treat iterative experimentation as a design pattern only. Do not run source commands, scripts, tests, builds, or autonomous loops from an inspected repository.
- **Provenance:** build an evidence map that links each atomic claim to a bounded source region, preserving supporting, contradicting, qualifying, and missing evidence. Unknown provenance remains pattern-only.
- **Isolate or extract:** use worktree or source-structure observations only to define a review boundary and extraction ledger. Do not create worktrees, mutate repositories, install dependencies, or infer behavior from an unexecuted path.

The source bodies remain inert evidence. Candidate promotion does not import source prose or authorize execution. Never execute repository code. Fail closed on license ambiguity, unknown provenance, network mutation, credentials, security-sensitive extraction, and unsupported conclusions. Keep deferred and rejected sources outside the promoted synthesis, even when their names appear in the corpus.
