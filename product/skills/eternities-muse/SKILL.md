# Eternities Muse

Muse turns visual ambition into a coherent system with a visual law, semantic tokens, interaction states, accessibility, performance budgets, and acceptance evidence. Choose the route that owns the unresolved visual decision; once direction is settled, implementation can proceed under its contract.

## Choose the route

- **Visual forensics** extracts identity, tokens, components, layout, responsive states, accessibility, confidence, and reconstruction risks from supplied artifacts.
- **Interface art direction** chooses one generative visual law and translates it into hierarchy, tokens, component grammar, breakpoints, states, signature moments, and implementation acceptance.
- **Motion story** gives each scene or transition a narrative job, visible cause, timing, reduced-motion equivalent, and device tier.
- **Visual acceptance** freezes build, viewport, content, seed, camera, timing, and configuration, then checks states, temporal behavior, access, and budgets.
- **Interface accessibility** audits or repairs semantics, keyboard order, focus, contrast, zoom, motion, async status, and fallback behavior with reproducible fixtures.
- **Operational system visualization** maps observed freshness, capacity, retries, or partition ownership to inspectable marks without inventing telemetry or changing the system being explained.

## Working method

1. Separate observed, extracted, inferred, and proposed facts. Recover explicit variables before guessing values, and name confidence and open questions.
2. State one visual law that can decide palette, type, spacing, shape, imagery, motion, and density together. Name exceptions instead of letting them accumulate invisibly.
3. Treat accessibility, responsive behavior, loading, reduced motion, and GPU cost as design inputs. Map every motion beat to orientation, causality, demonstration, or story.
4. For asynchronous interfaces, design state, focus, announcement, cancellation, retry, and stale-response behavior together. For rendered systems, measure geometry in the final viewport rather than trusting source assumptions.
5. Freeze an acceptance matrix with representative content, extremes, diagnostic states, keyboard and focus checks, fallback behavior, temporal samples, and rejection thresholds.

## Deliverable and finish

Return a visual evidence map, direction contract, motion contract, accessibility issue ledger, or acceptance receipt with source conditions, tokens, constraints, proposed changes, performed effects, and proof limits. Finish when the system has a coherent law and a condition that could reject it. The extension procedures are in [methods.md](references/methods.md).

A visual audit or direction contract is a checkpoint when the user also requested an authorized local repair or implementation. Continue into the component, state, or token change and rerun the relevant fixture without requesting permission already granted. Pause only for missing authority or material rights, accessibility, performance, or evidence risk.

Example: find that an async error leaves focus behind, patch the state transition and live-region behavior, then rerun keyboard, stale-response, and reduced-motion cases.
