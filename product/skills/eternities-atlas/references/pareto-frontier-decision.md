# Finite Pareto frontier: declared-input arithmetic and evidence boundary

Use this Atlas route when the question is which finite alternatives are **not dominated** across at least two predeclared quantitative objectives. A frontier is a set of remaining trade-offs, not a recommendation to pick any one of them. A weighted score, one winner, forecast, causal effect, or automatic policy choice is a different task.

## Declare the finite comparison

1. Name the alternatives and hard feasibility conditions. For each objective, predeclare direction (max or min), unit, evidence tier, measurement basis, population/time support, and source location. Do not invent missing measurements, feasibility records, labels, conversions, or a reviewer identity. Matching label strings and a feasible flag are **not** evidence that values are real or comparable.
2. Freeze exact UTF-8 JSON input bytes and SHA-256. Use the reviewed pareto-oracle-v2.input.v1 schema: unique row IDs; 2–16 objectives; explicit direction and unit/tier/basis labels; feasibility plus evidence ID; complete eligible measurements; an invalidPolicy of reject-row or hold; and a pair budget. Hard-infeasible rows are excluded before comparison. Under reject-row, invalid numeric rows are listed separately, not repaired. Missing policy or inconsistent metadata holds the arithmetic case.
3. A finite synthetic or exploratory calculation may proceed on **declared** values. Before using it for a consequential real-world recommendation, an externally authorized evidence owner—not the calculating agent—must separately review the exact input digest, source measurements, hard-gate evidence, comparability, freshness, uncertainty, and rights. This owner review is outside the math checker. A caller-supplied name, evidence ID, or purported approval cannot self-certify it. Unlike units, cohorts, anchors, periods, or uncertain estimates whose order may reverse require an owner-approved conversion, uncertainty rule, or separate analysis before consequential use.

## Compute and independently check

4. This optional route requires Node >=24. The [local gate](../resources/pareto/pareto-gate.mjs) uses the exact packaged [v3 oracle](../resources/pareto/pareto-oracle.mjs) and [independent output verifier](../resources/pareto/verify-output-v1.mjs) at pinned SHA-256s. Run the packaged oracle and verifier suites before use. If runtime, dependency digest, suite, input, or budget fails, HOLD this route; do not substitute agent arithmetic. The other Atlas routes do not require Node.
5. Call assessParetoDecision with a normalized frontier request and frozenInputBytes. There is no evidence-review parameter. The gate executes the already-hashed oracle source snapshot with a fixed bounded Node module invocation, not a mutable file path. It passes **the same input bytes** and raw oracle output to the independent verifier. Only VERIFIED_DECLARED_INPUT_PARTITION with successful oracle exit yields declared-input-frontier; oracle holds, verifier rejection, timeout, inconsistent status, and malformed output yield HOLD without classifications. Neither program authenticates measurements, feasibility, comparability, reviewer authority, or rights.
6. A dominates B only if A is no worse in every declared direction and strictly better in at least one. Equal vectors retain separate IDs unless another row dominates them. Keep direct witnesses, invalid rows, and infeasible rows visible. Do not rank frontier members, add a composite score, choose a winner, or infer preferences from row order.

## Report and stop boundary

Return the question, frozen input digest, objective schema, exact oracle/verifier hashes and test exits, frontier IDs, dominated IDs with direct retained witnesses, invalid/infeasible IDs, eligible and pair counts, and unresolved preference or measurement questions. Label this a **declared-input mathematical partition**. Report source and hard-gate references as caller declarations unless separately reviewed; state that arithmetic checking did not validate source truth, comparability, feasibility, rights, domain meaning, or agent judgment. An empty frontier from zero eligible rows is an exclusion report, not a recommendation.

For any consequential real-world recommendation, HOLD until the external owner review is established and bound to this exact input; the math result alone cannot authorize action. If the calculating agent itself supplies a review claim, treat it as unverified, not as a gate pass. A request for one winner or weights remains outside this route even after owner review. Preserve original rows and failed checks; repair and re-freeze before rerunning. This is an original finite-comparison method with pattern provenance recorded in development receipts. No upstream code or text is included in this product method.
