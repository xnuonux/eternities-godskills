# Refinery method cards

## Neutral contract

Write outcome, success evidence, inputs, outputs, operations, effects, positive and negative triggers, dependencies, failure modes, and termination. Use plain capability language so the contract remains valid outside the source ecosystems.

## Provenance and disposition

For each inspected source, record repo-relative path or stable source id, digest when available, license class or uncertainty, mechanisms extracted, and disposition. Independent implementation means the new text and structure were authored from the contract; pattern reference means a concept informed the design; rejected or deferred sources remain outside the promoted synthesis. Do not claim legal clearance.

## Checks and receipt

Use direct, paraphrase, exclusion, conflict, boundary, and portability cases. If an executable checker is available, preserve its exact command and output; otherwise run structural checks and say runtime evaluation was not available. The receipt records candidate and baseline bytes or identifiers, changed surfaces, token or word bounds, effects, failed gates, and current maturity. It never turns a fixture into agent-performance evidence or grants installation authority.
