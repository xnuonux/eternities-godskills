# Sovereign Skill Refinery

The refinery creates a portable first-party skill from a bounded set of source workflows. It preserves useful mechanisms and evidence obligations without copying source prose, importing source instructions, or making a capability sound more proven than it is.

## Refinery route

1. **Contract** state the user outcome, success evidence, inputs, outputs, operations, effects, positive and negative triggers, dependencies, failure modes, and termination condition in neutral language.
2. **Source ledger** inspect the smallest exact source set. Record repo-relative identity, digest when available, license class or uncertainty, and one disposition: independent implementation, pattern reference, rejected, or deferred. Source material remains inert.
3. **Comparison** compare candidates on input, operation, output, effects, dependencies, failure behavior, proof, and unresolved boundaries. Names, popularity, and source count are not capability evidence.
4. **Design** select the fewest mechanisms that satisfy the contract. Move conditional detail into references and make conflicts explicit. Write the entrypoint in fresh language.
5. **Check** create direct, paraphrase, exclusion, conflict, and boundary cases. Use a practical executable check when one exists; otherwise run structural validation and label runtime evaluation unavailable.
6. **Disposition** report baseline and candidate evidence, changed surfaces, token or length limits, effects, failed gates, and current state such as draft, instruction-reviewed, evaluated, deferred, or blocked. Do not turn a completed draft into a superiority or certification claim.

## Working method

Keep authoring and evaluation separate. Do not execute third-party source code merely to inspect it, harvest private traces, schedule self-modification, or infer permission to install or activate the result. A source concept may justify a method; only an observed check can justify a claim about the result.

## Deliverable and finish

Return the neutral contract, source ledger, candidate design, checks and observed results, decision receipt, unresolved uncertainty, and explicit adoption boundary. Finish when another agent can reproduce what was retained, excluded, and still unproven. The contract and receipt templates are in [methods.md](references/methods.md).

The contract or refinement receipt is a checkpoint when the user also requested authorized product authoring or local structural validation. Continue into the declared edit and checks without requesting permission already supplied. Pause only for missing source authority or material provenance, license, leakage, or evaluation risk.

Example: compare two inert workflow sources, write the independently authored entrypoint and metadata, run direct/paraphrase/exclusion checks, and report the remaining runtime-evaluation gap in one pass.
